# Foodie — Restaurant Discovery & Ordering Demo

A portfolio-oriented, Zomato-inspired demo built with Django, PostgreSQL/SQLite, HTML, CSS, and JavaScript. It is an independent educational project and is not affiliated with Zomato.

## Features

- Video-backed hero homepage and responsive restaurant browsing
- 65 fictional sample restaurants with broad veg/non-veg menu variety
- Restaurant/cuisine/dish search and cuisine/vegetarian filters
- Django registration/login; login-required checkout and order history
- Cart, delivery-area selector, coupons, simulated payment success/failure
- Database-backed reviews, favourites, order tracking, and manager dashboard
- Django admin and JSON API endpoints

## Run locally (Windows)

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

Open `http://127.0.0.1:8000/`. You can also run `RUN_FOODIE.bat` from Windows.

## Deploy publicly on Render + Neon

The repository includes `render.yaml` and `build.sh` for Render deployment. Use Neon PostgreSQL so user accounts/orders are not stored on Render's temporary local filesystem.

1. Push this repository to GitHub.
2. Create a free PostgreSQL project at <https://neon.tech/>.
3. In Neon, click **Connect**, select the database/branch, and copy the PostgreSQL connection string (it includes `sslmode=require`). Keep it private.
4. Open <https://dashboard.render.com/blueprints> and choose **New Blueprint Instance**. Connect this GitHub repository.
5. Render reads `render.yaml`. When prompted for `DATABASE_URL`, paste the Neon connection string. The Django secret key is generated by Render.
6. Apply the Blueprint and wait for the build/deploy to finish. Open the `onrender.com` URL shown in the Render dashboard.
7. If you change code later, commit and push to GitHub; Render auto-deploys new commits on the linked branch.

If Render does not prompt for `DATABASE_URL`, open the created web service → **Environment** → **Add Environment Variable**, set key `DATABASE_URL`, value to the Neon connection string, save, and redeploy.

## Hosting notes

- Render's free web services may sleep after inactivity, so the first visit after a quiet period can take around a minute to wake up. See <https://render.com/docs/free>.
- Use a managed Postgres database such as Neon; Render free web service filesystems are ephemeral, so a local SQLite database may reset after restarts/redeploys. See <https://render.com/docs/free> and <https://neon.com/docs/introduction/plans>.
- Payments are simulated and do not contact a payment provider. Tracking is a database status flow, not live GPS. Delivery area is manually selected.
- The hero video and Unsplash images are remote, so visitors need internet for those external assets.
- Never commit passwords, private connection strings, API keys, or `.env` files.
- For real production commerce, add proper payment integration, fraud/security review, email verification, privacy/legal pages, monitoring, and tests.
